# Changelog

All notable changes to ScrapePy are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [semantic versioning](https://semver.org/).

## Unreleased

### Added

- `run_summary.json` lists every fetched page that gave no Markdown file under `no_markdown` with the reason (`too short`, `empty`, `error page`, `non-HTML`, `converter failure` and others), with `no_markdown_reasons` counts, and nearly empty JavaScript pages under `needs_render` (url and size) so they can be fetched again with `-j`. Each of these lists keeps its first 200 entries, with exact counts and a `truncated` list; an unchanged page is listed in `no_markdown` again with the reason stored in the cache. The crawl log prints the same counts. The schema version is unchanged: these are new fields.
- `--refuse-private-redirects` (off by default): a redirect to a loopback, link-local (including 169.254.169.254), private, IPv6 unique local or carrier-grade NAT address, or to a host that resolves to one, is not followed. Every hop of page, reconnaissance, robots.txt, feed, asset and document requests is checked and a refused page is recorded as failed. Reserved, multicast and benchmarking ranges, IPv4 addresses carried in IPv6 (IPv4-mapped or -compatible, NAT64, 6to4) and `.localhost` names are refused too. The start URL, redirects back to the start URL's own host and port, and everything in the browser modes (the browser's redirects and the images, scripts and icons it loads while rendering) are not checked, and a host whose DNS answer changes between the check and the request (DNS rebinding) is not caught.
- `--allow-sitemap-host HOST` (repeatable): sitemaps on this host are fetched when robots.txt or a sitemap index lists them.
- `--no-cloudflare-solve`: the browser modes do not try to solve Cloudflare challenges.
- `--obey-robots` applies robots.txt: URLs it disallows are skipped and its `Crawl-delay` is waited out. It is what the default did before; see the default change below.
- `--documents pdf,docx,xlsx,csv` (off by default): a crawl also downloads the documents its pages link to on the same site and converts each to Markdown with page-style frontmatter plus `page_type: document`, `file_type`, `pages` and `linked_from`. Originals are saved under `files/<site>/`, outside `MarkdownSites`. Documents follow the crawl's scope, targeting, robots.txt and pacing rules, count towards `--max-pages`, and are capped in size (`--max-document-mb`, default 25), pages, rows, columns and characters. Encrypted, corrupt and oversized files and zip bombs are recorded as failed; scanned PDFs with no text layer and `.doc` or `.xls` links are recorded as skipped. Redirects are followed only within the site, and a download has a 300 second deadline. Each conversion runs in its own process with memory and CPU limits and is killed after 120 seconds. `run_summary.json` gets a `documents` object. The libraries are an optional extra, `scrapepy[documents]` (pypdf, pdfminer.six, python-docx, openpyxl); without it `--documents pdf`, `docx` or `xlsx` exits 2 with a one-line message.
- Targeted crawls: `--include` and `--exclude` path patterns, `--max-depth`, `--max-pages` (with `stopped_by_limit`), `--urls-file` for many start URLs in one run, `--only-recipes`, `--site-name` for a shared output folder, and `--follow-next` for pagination. A start URL with a query string (a site search) is fetched as given. `run_summary.json` gets a `targeting` object. With any of these options, a start URL with a query string (a site search) is fetched as given, for its links. Without them a crawl is unchanged.
- `--markdown-only`: Markdown and run state only, with no HTML mirror and no image or asset downloads. Links and images stay absolute URLs, and every request is a page or reconnaissance request, paced and (with `--obey-robots`) checked against robots.txt.
- `docs/MARKDOWN-OUTPUT.md`, the output contract for tools that read the Markdown.
- `canonical_url` in frontmatter when the page declares a different same-site canonical (`url` stays the fetched address), and `duplicates` in `run_summary.json`.
- Recipe pages: schema.org Recipe data (JSON-LD, or simple microdata) is written as fixed `## Recipe details`, `## Ingredients`, `## Method` and `## Nutrition` sections, with nutrition values kept exactly as published and absent ones marked "not stated". The ingredient and method lists are removed from the page text, which follows under `## Page text`. Frontmatter gains `page_type: recipe`, `recipe_category`, `recipe_cuisine`, `servings`, `total_time` and `keywords`. Page text is removed only when it repeats an ingredient or step exactly, so notes and qualifiers are never lost; step numbers are removed only when they are clearly numbering and published numbers keep their text. Broken or unusual JSON-LD never stops a page converting.
- Feeds: an RSS 2.0 or Atom feed URL (detected from paths such as `/feed` and `/rss.xml`, or forced with `--feed`) is fetched once and each entry becomes a Markdown file with `page_type: feed_entry`, `date_source: FEED` and `author`. `--max-articles` caps the entries (50 by default). `run_summary.json` gains a `feed` object listing written, unchanged, skipped and teaser entries. Entry dates keep the precision they were published with. A DOCTYPE is removed before parsing, so entities are never expanded and nothing is fetched or read. Entry links are not followed. No new dependency.

### Changed

- robots.txt is read up to its first 512 KB, at most 50 of its `Sitemap:` URLs are fetched, and a sitemap from robots.txt or a sitemap index on another host is not fetched unless that host is given with `--allow-sitemap-host` (`www.` and the bare host count as the same site; hosts are compared lowercase, without a trailing dot and in punycode).
- Default change: robots.txt is no longer applied by default. ScrapePy skips no URL because robots.txt disallows it and does not wait for a `Crawl-delay`, and a robots.txt that cannot be read (5xx, unreachable) no longer stops a run. `--obey-robots` restores the old default, with the rules matched as before (RFC 9309). `--ignore-robots`, the old opt-out, is still accepted and does nothing, its warning is no longer printed, and combining it with `--obey-robots` exits 2. Without `--obey-robots`, robots.txt is requested only to read its `Sitemap:` lines, by the default crawl, `-j` and `--audit` when reconnaissance runs; `-1`, `--swagger`, `-d`, feed mode and a targeted crawl that skips reconnaissance no longer request it. `--wait` and the concurrency cap are unchanged. `run_summary.json` gains `options.obey_robots`; `options.ignore_robots` stays and is now true unless `--obey-robots` is given.
- Frontmatter is written with `yaml.safe_dump`, so values such as `yes`, `null`, `123` or text with colons, quotes and newlines load back unchanged. Strings are now quoted in YAML's usual way (single quotes where needed).
- Markdown is better for indexing: one H1 and no skipped heading levels, the main content found on listing pages without a known content container, headings inside card links kept, truncated link text expanded from its title, button furniture removed while accordion and FAQ questions, option lists and textarea text are kept, code fenced with its language.
- A page whose Markdown matches a file already written in the same run is not written twice.
- Section URLs ending in `index.html` map to the section's own `_index.md`; listing pages no longer get a visible date from the server's Last-Modified header.

### Fixed

- Valid pages were rejected as error pages when `>404<` or `>Not Found<` appeared anywhere in the HTML (a code sample) or the title contained a word such as "Errors" or a number such as 500. A 200 page is now an error page only when its title or first H1 names an error (a short title or H1 holding 404, 403 or 410 in any language, 500, 502 or 503 alone or beside a word for "error", or an English error phrase), or when it is a short storage-service error document; body text is no longer read for this. A 200 page whose title and H1 look normal but whose body says "page not found" is now kept, deliberately: such a page is usually too short to give a Markdown file and is then listed under `no_markdown`.
- A page whose body did not decode with its declared charset failed with `UnicodeDecodeError`. Bodies are now decoded with a UTF-16 or UTF-32 byte order mark, the declared charset, the `<meta>` charset and UTF-8; then a mostly UTF-8 body keeps UTF-8 with its bad bytes replaced and any other is read as Windows-1252, and last UTF-8 with replacement. A Content-Type charset Python does not know, which made the fetch itself fail, now leads to a second plain request for the raw body; `run_summary.json` lists such pages under `encoding_fallbacks`. Binary data served as a page is skipped as not HTML.
- `--documents`: a DOCX of many tiny paragraphs converts in seconds instead of running into the 120 second limit (paragraph styles are read from a table built once, not looked up per paragraph); a conversion that stops is reported with what happened (CPU limit, memory limit, crash, or an exit without a result) instead of one catch-all reason, and output a library prints no longer affects the result or grows memory (stdout is counted, only the end of stderr is kept); the conversion process gets a minimal environment, so proxy variables and credentials stay out of it, and stops when ScrapePy is killed.
- `-1` wrote every page to `index/_index.md` with the site's root as its `url`, so each `-1` run on a host replaced the previous page and search indexes showed the wrong address. `-1` now saves its page through the crawl pipeline: `url` is the address the browser ended on (same host), the file is named from that path with the crawl's hash-suffixed names when the path is taken, the query string stays in `url`, the incremental cache reports an unchanged page as unchanged, and `run_summary.json` is written. It also downloads the page's assets and names the HTML copy after the page, as a crawl does. `--site-name` now works with `-1`. The browser requests the URL exactly as given, trailing slash included. Files written by the old naming are not migrated: delete `index/_index.md` and `index.html` in the site folders by hand.
- A page with a sidebar or widget container nested inside another one failed to convert (`AttributeError: 'NoneType' object has no attribute 'get'`): containers inside one already removed are now skipped, and the same guard covers H1 and image clean-up.
- `--proxy` is used by every request: page fetches, reconnaissance, robots.txt, sitemap and feed requests and feed mode, not only the browser and asset downloads. It is validated (`http`, `https` and `socks` schemes) and its credentials are masked in console output, logs, errors and `run_summary.json`.
- Accordion labels that contain a furniture word ("Next steps after your application", "Our cookie recipes", "2024") lost their text; furniture is now matched on the whole label, and number-only selects are kept unless named as a quantity.
- A heading above the page's H1, such as a site tagline, became the title. The first H1 is now the title and headings above it are kept as paragraphs.
- Code containing a line of three backticks broke out of its fence, headings in a quote inside a list item were not normalised, and `javascript:`, `data:` and `tel:` links got `.md` appended.
- A page's alternate formats (`<link rel="alternate">` JSON, Markdown or feed versions) and `.json`, `.xml`, `.rss` and `.atom` links were crawled as pages, and responses that are not HTML were converted, so data files overwrote real pages. They are no longer queued or converted.
- A second URL mapping to a file already written in the same run (`/about` and `/about/`) overwrote it. A page now never replaces another URL's file: the later one gets a hash-suffixed name, listed under `renamed` in `run_summary.json`, and the URL-to-file assignment is kept in the cache so every URL keeps its file. Non-HTML responses are no longer saved in the default HTML copy.
- A junk-removal rule deleted every linked H2 or H3 heading, and links with a title attribute got `.md` appended after the title.

## 0.2.0

### Added

- robots.txt is enforced following RFC 9309 (longest match wins, `*` and `$` wildcards in a linear-time matcher, exact product-token groups, up to five http or https redirects, a 10 second single-attempt fetch, and bounded pattern and URL lengths) in the default crawl, `-j`, `-d`, `-1`, `--swagger` and `--audit`, and `Crawl-delay` sets a minimum gap between requests to the site. A 4xx robots.txt allows everything; a 5xx or unreachable one disallows everything. Instagram mode does not check robots.txt.
- `--ignore-robots` turns robots.txt rules and `Crawl-delay` off and prints a warning.
- `--user-agent` sets the User-Agent for page, browser and asset requests and is matched against robots.txt groups.
- `--output-dir` (`-o`) chooses the folder under which `ScrapedSites/` and `MarkdownSites/` are created.
- `run_summary.json` is written after every crawl with counts and lists of new, changed, unchanged, failed and robots-blocked pages. It is replaced with a `running` placeholder when a crawl starts, and an interrupted crawl writes it with `status: interrupted`. The schema is in the README.
- Documented exit codes: 0 success, 1 nothing fetched or every fetch failed, 2 bad arguments, 130 interrupted (Ctrl+C), 143 terminated (SIGTERM). SIGTERM is handled like Ctrl+C: the cache is saved and the summary written.
- `scraped_at` and `content_hash` in every Markdown file's frontmatter.
- `--no-index-pages` skips the generated `_index.md` section listings.
- `--version`, `scrapepy.__version__` and `python -m scrapepy`.
- Package metadata (readme, project URLs, keywords, classifiers), a `dev` extra with pytest, and a GitHub Actions workflow running the tests on Python 3.11, 3.12 and 3.13.

### Changed

- Default concurrency is 4 instead of 10.
- Page requests, prefetches included, now wait on a per-host rate limiter instead of sleeping after each page, so a prefetch burst keeps the `--wait` gap.
- Reconnaissance requests (sitemaps, feeds, homepage) are spaced out instead of sent all at once.
- Frontmatter no longer writes `null` for a missing `date`, `date_source` or `page_type`; missing fields are left out, as the README already said.
- Generated `_index.md` pages write `page_type: section` instead of `SECTION`.
- `--wait` and `-c` reject negative or zero values, and a bad `--since` or `--recent` is reported as an argument error instead of a traceback.
- The Markdown output folder is derived once on the config instead of by replacing `ScrapedSites` in paths.
- The build requires setuptools 77 or later, which the `license` and `license-files` fields need.
